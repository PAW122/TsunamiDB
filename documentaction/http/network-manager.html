Network Manager

Dedicated documentation page for TsunamiDB's P2P layer. This section is intended to grow as the distributed feature set expands.

Purpose

Network Manager connects TsunamiDB nodes over WebSocket, exchanges table catalogs and routes reads to peers that advertise the requested table. The goal is to let one node answer requests using data stored on another node.

Current Capabilities

CapabilityStatus
Peer-to-peer node connectionsImplemented.
Heartbeat and stale-peer cleanupImplemented.
Table catalog exchangeImplemented.
Table-aware distributed read routingImplemented.
Encrypted node-to-node transport with shared secretImplemented.
Distributed write placement and replication policiesPlanned.

Transport Settings

Environment VariableRole
TSUNAMI_NETWORK_SECRETEncrypts node-to-node protocol frames with a shared secret.
TSUNAMI_NETWORK_ADVERTISE_ADDROverrides the address advertised to peers.

Example Startup

# Node A
$env:TSUNAMI_NETWORK_SECRET="cluster-secret"
$env:TSUNAMI_NETWORK_ADVERTISE_ADDR="10.0.0.1:5855"
.dist/TsunamiDB.exe 5855 10.0.0.2:5855

# Node B
$env:TSUNAMI_NETWORK_SECRET="cluster-secret"
$env:TSUNAMI_NETWORK_ADVERTISE_ADDR="10.0.0.2:5855"
.dist/TsunamiDB.exe 5855 10.0.0.1:5855

Routing Model

Client -> Node A
Send: GET /read/users/user-1

Node A -> Node B
Send: P2P request for table users

Node B -> Node A
Response: stored bytes

Node A -> Client
Response: HTTP 200
