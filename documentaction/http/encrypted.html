HTTP Encrypted Values

Encrypted endpoints encrypt data before storage and decrypt it on read. The caller provides the encryption key in a request header.

The save_encrypted route sends plaintext data to active subscribers for the key. Do not expose subscriptions for sensitive keys unless that behavior is acceptable.

POST /save_encrypted/{table}/{key}

InputValue
Header encryption_keyRequired passphrase/key material.
BodyPlain bytes to encrypt and store.
Success bodysave
 
curl -X POST http://localhost:5844/save_encrypted/secrets/api-token \
  -H "encryption_key: correct-horse-battery-staple" \
  --data-binary "secret value"

GET /read_encrypted/{table}/{key}

Uses the same encryption_key header to decrypt the stored value. If the key is missing locally, the route asks P2P peers and decrypts the returned encrypted bytes.

curl http://localhost:5844/read_encrypted/secrets/api-token \
  -H "encryption_key: correct-horse-battery-staple"
