HTTP Incremental Tables

Incremental tables store many fixed-size entries behind one key. They are useful for append-heavy logs, feeds and event streams.

POST /save_inc/{table}/{key}

Creates incremental table metadata if missing, then writes one entry. Response is JSON: {"id":"0"}. If max_entry_size does not match an existing table, the existing size is used and a warning can be returned.

HeaderRequiredValuesMeaning
max_entry_sizeFirst writeuint64 bytesFixed maximum size of every entry.
entry_keyNostringStable logical lookup key. Must be unique per incremental table.
idNouint64Target position for insert or overwrite.
modeNoappend, overwriteDefault is append. With id, append means insert at position.
count_fromNotop, bottomDefault in code is top.
 
curl -X POST http://localhost:5844/save_inc/events/activity \
  -H "max_entry_size: 256" \
  -H "entry_key: event-001" \
  --data-binary "{\"type\":\"login\",\"user\":\"jane\"}"

GET /read_inc/{table}/{key}

read_typeExtra headerResponse
by_idid{"data":"..."}
by_keyentry_key{"data":"..."}
first_entriesamount_to_read[{"id":0,"data":"..."}]
last_entriesamount_to_read[{"id":0,"data":"..."}], where 0 is the newest entry in that response.
 
curl http://localhost:5844/read_inc/events/activity \
  -H "read_type: by_key" \
  -H "entry_key: event-001"

curl http://localhost:5844/read_inc/events/activity \
  -H "read_type: last_entries" \
  -H "amount_to_read: 10"

GET /delete_inc/{table}/{key}

Deletes the backing incremental table file, drops the entry-key index, removes KV metadata and notifies subscribers with a deleted event.

curl http://localhost:5844/delete_inc/events/activity

Behavior Notes

  • Payload length must be less than or equal to max_entry_size.
  • Duplicate entry_key returns 409.
  • Incremental read responses serialize entry data as strings; base64 encode arbitrary binary data in the application layer.
  • Successful writes emit inc_table_update subscription events.
