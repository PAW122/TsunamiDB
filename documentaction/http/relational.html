Relational HTTP API

The relational API exposes fixed-row tables through public-api v1 under /rel/.... It supports schemas, row CRUD, equality and LIKE selects, indexes, compaction and a compact SQL subset.

Source files: data/relational, servers/public-api/v1/routes/relational.go, and route registration in servers/public-api/v1/Api.go.

Current Storage Model

Each table is stored in db/rel. Rows are fixed-size records, so reading by row ID is a direct file offset lookup.

db/rel/{table}.schema
db/rel/{table}.rows
db/rel/{table}.free
db/rel/{table}.index.{column}
db/rel/{table}.index.{column}.trigram
FilePurpose
.schemaCalculated schema, row size, column offsets and index flags.
.rowsFixed-size encoded rows with active/deleted flag and row version.
.freeDeleted row IDs. Current inserts still append; reuse is not implemented yet.
.index.{column}Equality index used by op: "eq".
.index.{column}.trigramTrigram index used by indexed LIKE searches.

Endpoint Index

MethodPathUse
GET/rel/schema/{table}Load calculated schema.
POST/rel/schema/{table}Create table schema.
POST/rel/{table}/insertInsert one row.
GET/rel/{table}/row/{rowID}Read one active row.
PATCH/rel/{table}/row/{rowID}Update selected columns.
POST/rel/{table}/row/{rowID}Update selected columns; alias for clients without PATCH.
DELETE/rel/{table}/row/{rowID}Mark row as deleted.
POST/rel/{table}/selectSelect rows by equality or LIKE predicate.
POST/rel/{table}/index/{column}Create equality index.
POST/rel/{table}/trigram-index/{column}Create trigram index for string LIKE queries.
POST/rel/{table}/compactRemove deleted rows, rewrite row IDs and rebuild indexes.
POST/rel/sqlExecute one compact SQL statement and return SQLResult.

SQL Endpoint

POST /rel/sql accepts one SQL statement per request. The body can be raw SQL or JSON with a query field.

curl -X POST http://localhost:5844/rel/sql \
  -H "Content-Type: text/plain" \
  --data "SELECT row_id, name, price FROM products WHERE name LIKE '%wid%' ORDER BY price DESC"
curl -X POST http://localhost:5844/rel/sql \
  -H "Content-Type: application/json" \
  -d '{"query":"SELECT * FROM products WHERE id = 1"}'

Supported SQL

SHOW TABLES;

CREATE TABLE products (
  id uint64 PRIMARY KEY,
  name string(32) INDEXED TRIGRAM,
  price uint64,
  active bool
);

INSERT INTO products (id, name, price, active)
VALUES (1, 'widget', 100, true);

SELECT * FROM products;
SELECT row_id, name, price FROM products WHERE id = 1;
SELECT row_id, name, price FROM products WHERE name LIKE '%wid%';
SELECT row_id, name, price FROM products ORDER BY price DESC;

UPDATE products
SET price = 175, name = 'bluewidget'
WHERE row_id = 0;

DELETE FROM products WHERE id = 1;

CREATE INDEX products_price_idx ON products (price);
CREATE TRIGRAM INDEX ON products (name);

SQL Result

{
  "operation": "select",
  "table": "products",
  "rows_affected": 1,
  "rows": [
    {
      "row_id": 0,
      "values": {
        "name": "widget",
        "price": 100
      }
    }
  ]
}

Supported SQL column types are uint64, int64, bool, float64, string(N), string[N], blob_ptr and row_ref. WHERE supports one = or LIKE predicate, including the synthetic row_id column. ORDER BY supports ASC and DESC. Joins, ranges, aggregates, ALTER TABLE, DROP TABLE and multi-statement batches are not implemented.

Create Table

curl -X POST http://localhost:5844/rel/schema/products \
  -H "Content-Type: application/json" \
  -d '{
    "columns": [
      {"name": "id", "type": "uint64", "indexed": true},
      {"name": "name", "type": "string", "size": 32, "indexed": true, "trigram_indexed": true},
      {"name": "price", "type": "uint64"},
      {"name": "active", "type": "bool"}
    ]
  }'

The schema name field can be omitted. If present, it must match the table name in the URL.

Insert Row

curl -X POST http://localhost:5844/rel/products/insert \
  -H "Content-Type: application/json" \
  -d '{
    "values": {
      "id": 1,
      "name": "widget",
      "price": 100,
      "active": true
    }
  }'

Response:

{
  "row_id": 0
}

Read Row

curl http://localhost:5844/rel/products/row/0

Response:

{
  "id": 1,
  "name": "widget",
  "price": 100,
  "active": true
}

Update Row

curl -X PATCH http://localhost:5844/rel/products/row/0 \
  -H "Content-Type: application/json" \
  -d '{
    "values": {
      "name": "bluewidget",
      "price": 175
    }
  }'

Only supplied columns are changed. The current implementation rewrites the row in place and rebuilds configured indexes.

Delete Row

curl -X DELETE http://localhost:5844/rel/products/row/0

The row is marked inactive and the row ID is appended to {table}.free.

Select Rows

Equality query:

curl -X POST http://localhost:5844/rel/products/select \
  -H "Content-Type: application/json" \
  -d '{"column":"name","op":"eq","value":"bluewidget"}'

LIKE query:

curl -X POST http://localhost:5844/rel/products/select \
  -H "Content-Type: application/json" \
  -d '{"column":"name","op":"like","value":"%widget%"}'

Response:

[
  {
    "row_id": 0,
    "values": {
      "id": 1,
      "name": "bluewidget",
      "price": 175,
      "active": true
    }
  }
]

Indexes and Compaction

curl -X POST http://localhost:5844/rel/products/index/name
curl -X POST http://localhost:5844/rel/products/trigram-index/name
curl -X POST http://localhost:5844/rel/products/compact

Compaction response contains rows_before, rows_after, removed, and a row_id_map from old row IDs to new row IDs.

Status Codes

StatusMeaning
200Read, update, delete, select, index creation or compaction completed.
201Schema or row created.
400Invalid schema, row values, row ID, JSON or predicate.
404Table or row not found.
405Wrong HTTP method.
409Table already exists.
500Corrupt rows file or unexpected storage error.

Manual Testing Tool

Open tools/relational-admin.html in a browser. Enter the public API host and port, then use the UI to create schemas, insert/read/update/delete rows, run selects, execute SQL, create indexes and compact tables.

Current Limitations

  • Deleted row IDs are recorded in .free, but inserts do not reuse them yet.
  • Update and delete rebuild configured indexes instead of applying a minimal delta update.
  • Row-reference joins are currently available in the Go package, not through HTTP.
  • The SQL layer is intentionally compact: one statement per request, no joins, no aggregates and no multi-statement batches.
