DLL Lib

This page documents the current DLL status and the recommended ABI shape for future native bindings.

Current repository state: there are no //export cgo functions and no committed -buildmode=c-shared DLL entrypoint. The existing lib/export package is a Go package, not a stable C ABI. Treat this page as implementation guidance until the DLL layer is added.

Recommended Build Shape

A Go DLL/shared library should be built from a dedicated package main file using cgo exports. Keep this separate from lib/export so the C ABI can stay stable while Go internals change.

# Windows DLL
go build -buildmode=c-shared -o tsunamidb.dll ./lib/dll

# Linux shared object
go build -buildmode=c-shared -o libtsunamidb.so ./lib/dll

ABI Rules

  • Do not return Go pointers to C callers. Return C-allocated memory and provide TsuFreeBuffer.
  • Use explicit byte lengths for binary input/output. Do not rely on null-terminated strings for data payloads.
  • Return integer status codes for write operations, for example 0 success and non-zero failure; expose details through TsuLastError.
  • For arrays such as regex key results, return UTF-8 JSON to keep ABI simple for C#, Python, Rust, C and C++ callers.
  • Document ownership of every returned pointer next to the function signature.

Example Consumer Contract

int TsuSave(const char* key, const char* table, const unsigned char* data, int dataLen);
TsuBuffer TsuRead(const char* key, const char* table);
void TsuFreeBuffer(void* ptr);

Until this layer exists, use the HTTP API for non-Go languages. It is stable today and covers more features than the current Go lib wrappers.
