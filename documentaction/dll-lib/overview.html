DLL Lib

This page documents the cgo DLL/shared-library wrapper for native bindings.

Current repository state: lib/dll exposes //export cgo functions over github.com/PAW122/TsunamiDB/lib/dbclient.

Build

The DLL/shared library is built from a dedicated package main file using cgo exports. It is separate from lib/export so native bindings do not import Go internals directly.

On Linux the equivalent of a Windows .dll is a shared object file with the .so extension. TsunamiDB builds it as .dist/libtsunamidb.so and exposes the same C ABI functions as the Windows DLL.

# Windows DLL
go build -buildvcs=false -buildmode=c-shared -o .dist/tsunamidb.dll ./lib/dll

# Linux shared object
go build -buildvcs=false -buildmode=c-shared -o .dist/libtsunamidb.so ./lib/dll

# Linux helper script
bash ./lib/dll/build.sh

ABI Rules

  • Do not return Go pointers to C callers. Return C-allocated memory and provide FreeBuf or FreeKeysArray.
  • Use explicit byte lengths for binary input/output. Do not rely on null-terminated strings for data payloads.
  • Return integer status codes for write operations: 0 success and -1 failure.
  • Document ownership of every returned pointer next to the function signature.

Example Consumer Contract

int Save(const char* key, const char* table, const char* data, int dataLen);
int Read(const char* key, const char* table, char** out, int* outLen);
void FreeBuf(char* ptr);

Read and ReadEncrypted use the Go library behavior and require InitNetworkManager before reads, even for single-node local usage.
