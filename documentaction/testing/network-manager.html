Network Manager

Quick local demo page for spinning up two TsunamiDB nodes, connecting them through the P2P layer, and feeding live traffic into tools/network-topology.html.

Source files: tools/example-NM-presentation/start-demo.ps1, stop-demo.ps1, traffic-loop.ps1, node-runner/main.go, and tools/network-topology.html.

Quick Start

# from repository root
powershell -ExecutionPolicy Bypass -File .\tools\example-NM-presentation\start-demo.ps1

# stop the whole demo
powershell -ExecutionPolicy Bypass -File .\tools\example-NM-presentation\stop-demo.ps1

The helper starts two isolated working directories under tools/example-NM-presentation/runtime, so both nodes keep separate db folders and do not fight over ports or on-disk data.

What The Demo Generates

  1. Node A stores one JSON record in table users.
  2. Node B stores one JSON record in table orders.
  3. The traffic loop keeps updating both records every 1.5 seconds.
  4. Node A repeatedly calls GET /read/orders/order-1, which forces a remote P2P read from node B.
  5. Node B repeatedly calls GET /read/users/user-1, which forces a remote P2P read from node A.

This is enough to make the topology tool show changing HTTP req/s and live out req/s / in req/s on both edges.

Manual Two-Node Startup

If you want to run the same setup manually, use the helper runner instead of the default main.go entrypoint. The main binary uses fixed ports 5844 and 5845, so two local nodes need a custom starter.

New-Item -ItemType Directory -Force .\tools\example-NM-presentation\runtime\node-a | Out-Null
New-Item -ItemType Directory -Force .\tools\example-NM-presentation\runtime\node-b | Out-Null

# shell A
Set-Location .\tools\example-NM-presentation\runtime\node-a
go run ..\..\node-runner `
  -api-port 6044 `
  -sub-port 6045 `
  -nm-port 6055 `
  -advertise-addr 127.0.0.1:6055 `
  -network-secret demo-cluster-secret

# shell B
Set-Location .\tools\example-NM-presentation\runtime\node-b
go run ..\..\node-runner `
  -api-port 6144 `
  -sub-port 6145 `
  -nm-port 6155 `
  -known-peers 127.0.0.1:6055 `
  -advertise-addr 127.0.0.1:6155 `
  -network-secret demo-cluster-secret

Seed Example Data

$user = @{
  customer_id = "cust-1001"
  name = "Anna Kowalska"
  tier = "pro"
  region = "eu-central"
} | ConvertTo-Json -Compress

$order = @{
  order_id = "ord-2026-0001"
  customer_id = "cust-1001"
  status = "created"
  warehouse = "wroclaw-01"
} | ConvertTo-Json -Compress

Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:6044/save/users/user-1" -ContentType "application/json" -Body $user
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:6144/save/orders/order-1" -ContentType "application/json" -Body $order

# remote reads through network-manager
Invoke-RestMethod -Uri "http://127.0.0.1:6044/read/orders/order-1"
Invoke-RestMethod -Uri "http://127.0.0.1:6144/read/users/user-1"

Use network-topology.html

  1. Open tools/network-topology.html in your browser.
  2. Paste both health endpoints into the left panel:
http://127.0.0.1:6044/health
http://127.0.0.1:6144/health
  1. Leave polling at 1500-2000 ms.
  2. Click Odswiez once if you started the page before the demo.
  3. Ignore the first sample if all rates are 0.0; the page needs a second poll to calculate deltas.

The quick-start script already knows these endpoints and, unless you pass -NoBrowser, opens the page with prefilled query parameters so the graph starts working immediately.
