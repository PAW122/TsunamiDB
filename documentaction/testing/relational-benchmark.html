Relational db

Benchmark page for relational storage, indexed selects, relation lookups and throughput-style stress tests.

Source files: data/relational/relational_benchmark_test.go, tests/special_relational_performance_test.go, and tools/relational-perf-report.ps1.

Microbenchmarks

# microbenchmarks: insert, read, select scan, select indexes, LIKE trigram, row_ref join
# use fixed benchtime so Go does not repeat expensive table setup during benchmark calibration
go test ./data/relational -run '^$' -bench BenchmarkRelational -benchmem -benchtime=100x -count=1

# smaller/larger seeded tables for read/select/join benchmarks
$env:TSU_REL_BENCH_ROWS='1000'
go test ./data/relational -run '^$' -bench 'BenchmarkRelational/(ReadByRowID|Select|Join)' -benchmem -benchtime=100x -count=1
BenchmarkMeaning
InsertNoIndexInsert into a table without secondary indexes.
InsertEqualityAndTrigramIndexesInsert into a table with equality and trigram indexes enabled.
ReadByRowIDDirect lookup of one row by row_id.
SelectEqualityScanEquality SELECT without an equality index, so the table is scanned.
SelectEqualityIndexEquality SELECT using an equality index.
SelectLikeScanLIKE query without a trigram index, so the table is scanned.
SelectLikeTrigramIndexLIKE query using a trigram index.
JoinRowRefIndexedPredicateRelation lookup with row_ref and an indexed predicate.
ColumnMeaning

ThroughputProcessed MB/s when Go can derive byte volume for that benchmark.
Memory/opHeap bytes allocated per operation.
Allocs/opHeap allocation count per operation.

Throughput and Saturation Tests

# throughput-style relational performance test with useful logs
$env:TSU_SPECIAL_TESTS='1'
$env:TSU_REL_PERF_DURATION='30s'
$env:TSU_REL_PERF_WORKERS='1'
$env:TSU_REL_PERF_ROWS='1000'
go test ./tests -run TestSpecialRelationalPerformance -count=1 -v

# saturation profiles for pushing the relational layer harder
$env:TSU_REL_SAT_DURATION='30s'
$env:TSU_REL_SAT_WORKERS='12'
$env:TSU_REL_SAT_ROWS='1000'
$env:TSU_REL_SAT_MODE='read'        # read, insert, select-eq, select-like, related-select, mixed
go test ./tests -run TestSpecialRelationalSaturation -count=1 -v

# one-command complex relational report
powershell -ExecutionPolicy Bypass -File .\tools\relational-perf-report.ps1
MetricMeaning
actions/sTotal API operations per second: reads, inserts, equality selects, LIKE selects and related selects.
reads/sReadRow(...) calls per second. In read mode one read means one row lookup.
inserts/sInsertRow(...) calls per second.
selects/sSelectRows(...) calls per second for equality and/or LIKE selects.
related/sJoinRowRef(...) calls per second.
rows/sRows returned per second by SelectRows(...) and JoinRowRef(...). This is not the same as actions/s.
wide-msWall-clock time of an extra broad SelectRows(...) probe that returns many rows before the throughput loop starts. For insert mode the value is n/a.
wide-rowsTotal rows returned by that broad select probe across worker tables.
ModeMeaning
readRepeated ReadRow(...) lookups.
insertRepeated InsertRow(...) writes.
select-eqRepeated equality SelectRows(...) queries.
select-likeRepeated LIKE SelectRows(...) queries.
related-selectRepeated JoinRowRef(...) relation queries.
mixedCombined loop of ReadRow + SelectRows(eq) + SelectRows(like) + InsertRow.
