TsunamiDB Documentation

TsunamiDB is a fast key-value database with HTTP endpoints, an in-process Go client library, P2P reads, encrypted values, incremental tables, and WebSocket subscriptions.

HTTP API

Public API for any language over HTTP. Includes raw key-value operations, encrypted values, incremental tables, relational tables, nested JSON, subscriptions, regex key lookup and health.

Open HTTP docs

Relational API

Fixed-row relational tables with schemas, row CRUD, equality and LIKE selects, compact SQL, indexes and compaction. Includes a manual browser tool.

Open relational docs

Network Manager

P2P layer for peer discovery, table catalogs, distributed reads and encrypted node-to-node transport.

DLL Lib

Native DLL/shared-library wrapper built with Go c-shared, with exported C ABI functions over lib/dbclient. On Linux the library is built as .dist/libtsunamidb.so, the .so equivalent of a Windows DLL.

Open DLL docs

Build Binaries

# Windows server binary
go build -buildvcs=false -o .dist/TsunamiDB.exe .

# Linux server binary
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 \
  go build -buildvcs=false -o .dist/TsunamiDB-linux .

# Windows + Linux server binaries via helper
.\build.bat

# Windows DLL
go build -buildvcs=false -buildmode=c-shared -o .dist/tsunamidb.dll ./lib/dll

# Linux shared object (.so, Linux equivalent of DLL)
go build -buildvcs=false -buildmode=c-shared -o .dist/libtsunamidb.so ./lib/dll

Runtime Ports

ServiceDefaultPurpose
HTTP Public APIhttp://localhost:5844Application reads, writes, deletes, incremental tables, health and subscription token endpoints.
WebSocket Subscriptionsws://localhost:5845/subClient-side real-time events after a one-time auth key is minted.
P2P Network ManagerOptional CLI argument, for example 5845Internal node-to-node WebSocket mesh used for distributed reads. Disabled when no port is provided.

Run TsunamiDB

# Local server without P2P network manager
.dist/TsunamiDB.exe

# Start P2P network manager
.dist/TsunamiDB.exe 5845

# Linux with P2P network manager
./.dist/TsunamiDB-linux 5845

# Join existing peers
.dist/TsunamiDB.exe 5845 10.0.0.2:5845 10.0.0.3:5845

The P2P network manager is optional. When no network-manager port is passed, TsunamiDB starts only the HTTP API on 5844 and the subscription WebSocket server on 5845. Passing the first CLI argument starts the P2P network manager on that port; any following arguments are known peers.

In practice, use a network-manager port different from the subscription WebSocket port. For example keep subscriptions on 5845 and run the P2P manager on 5855.

P2P Table Routing

The network manager now works as a P2P layer between TsunamiDB nodes. Each node advertises which tables it currently owns, and a read sent to node A can be forwarded to node B when node B has the requested table.

BehaviorDetails
DiscoveryPeers exchange a table catalog during connection setup and refresh it after local save or free.
Routingread and read_encrypted prefer peers that advertise the requested table instead of asking every connected node.
FallbackIf a node has not learned the catalog yet, it can still fall back to a wider peer query.
Transport securitySet TSUNAMI_NETWORK_SECRET to encrypt node-to-node frames over WebSocket using the shared secret.
Advertised addressSet TSUNAMI_NETWORK_ADVERTISE_ADDR when automatic IP detection is not the address peers should use.
 
# Node A
$env:TSUNAMI_NETWORK_SECRET="cluster-secret"
$env:TSUNAMI_NETWORK_ADVERTISE_ADDR="10.0.0.1:5855"
.dist/TsunamiDB.exe 5855 10.0.0.2:5855

# Node B
$env:TSUNAMI_NETWORK_SECRET="cluster-secret"
$env:TSUNAMI_NETWORK_ADVERTISE_ADDR="10.0.0.2:5855"
.dist/TsunamiDB.exe 5855 10.0.0.1:5855

With that setup, an application can call GET /read/users/user-1 on node A and still receive the value when the users table is stored on node B.

Data Model

Most public operations use a table and a key. The table maps to an internal data file and key map. Values are stored as bytes with TsunamiDB metadata, then decoded back to user bytes on read.

Path format for HTTP operations is usually /{operation}/{table}/{key}. Keep table and key URL-safe; encode special characters before sending requests.
